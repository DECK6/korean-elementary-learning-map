## 2. 방법

1. 내용 체계표 네 장(인쇄 p.7~10)에서 초등 3개 학년군(1~2 / 3~4 / 5~6) 열의 **지식⋅이해 내용 요소**를 그대로 옮겼다.
   과정⋅기능·가치⋅태도 범주는 초등 전체가 한 칸으로 묶여 있어 학년군 진행을 읽을 수 없으므로 사용하지 않았다.
2. 인접 학년군 요소끼리 **갈래(내용 요소 계열)** 를 판정했다(3절 규칙).
3. 갈래마다 앞 요소·뒤 요소를 학년군·영역의 성취기준 코드로 전개했다(4절 대응표, 데카르트 곱).
4. 초등 1~2 / 3~4 / 5~6학년군의 **성취기준 해설**과 **성취기준 적용 시 고려 사항** 전문을 읽고
   다른 성취기준의 선행 학습을 지목한 문장만 D계층으로 채택했다(6절).
5. 코드 순서·문서 배열·교육적 추론만으로 만든 쌍은 넣지 않았다. 미채택 후보는 7절에 전부 적었다.

내용 체계 개요(인쇄 p.4)의 "초⋅중학교의 지식⋅이해 범주는 학년(군)에 따라 위계성을 가지며, 영역 간에도
위계성을 고려하여 구성하였다"가 C계층 전체의 공식 근거 문장이다. 즉 같은 갈래의 학년군 진행은
문서가 스스로 위계로 규정한 것이고, 이 채굴은 그 위계를 코드 단위로 옮긴 것이다.

## 3. 갈래 판정 규칙 (C계층)

인접 학년군 요소 A(앞)·B(뒤)에 대해:

- **인정 조건**: A와 B가 같은 수학적 대상 계열(자연수 / 분수 / 소수 / 평면도형 / 시간 / 길이 / 들이 / 무게 / 그래프 …)에 속하고,
  B가 A의 **범위·단위·연산·조건을 확장한 것으로 요소 이름에서 직접 읽힐 때**만 같은 갈래로 본다.
- **금지**: 성취기준 본문·해설·교육적 추론을 갈래 판정 근거로 쓰지 않는다(그 근거는 D계층에서만 쓴다).
- **좁은 일치 우선**: 뒤 요소 B에 대해 앞 학년군에 더 좁은 이름 일치를 갖는 요소가 있으면, 더 넓은 후보는 제외한다.
  (예: `분모가 다른 분수의 덧셈과 뺄셈`의 선행은 `분모가 같은 분수의 덧셈과 뺄셈`만 인정하고 `분수`는 제외)
- **인접만**: 1~2 → 3~4, 3~4 → 5~6만 잇는다. 1~2 → 5~6 직접 연결과 같은 학년군 안의 쌍은 C계층에 넣지 않는다.
- **표에 없는 소주제 제외**: 내용 체계표에 내용 요소로 등재되지 않은 소주제는 C계층에서 다루지 않는다
  (`자연수의 어림셈` [4수01-08], `분수와 소수의 관계` [6수01-12], `입체도형의 공간 감각` [6수03-09~10]).

## 8. 한계

1. **갈래 판정은 요소 이름 기반의 사람 판단이다.** 내용 체계표는 학년군 열마다 내용 요소를 나열할 뿐 행 대응을
   선으로 그려 두지 않는다. pdftotext의 물리적 행 정렬은 열 배치 부산물이라 의미 대응이 아니다(예: 자료와 가능성에서
   `자료의 분류 / 그림그래프 / 평균`이 한 줄에 오지만 같은 갈래가 아니다). 3절 규칙을 명시하고 5·7절에 채택·미채택을
   전부 적어 재현·반박이 가능하게 했다.
2. **데카르트 곱 전개는 정밀도를 희생한다.** 한 갈래 안에서 어떤 성취기준이 어떤 성취기준의 직접 선행인지는
   고시가 말하지 않으므로 전부 이었다. 예컨대 `분수 → 분수의 곱셈과 나눗셈` 9건 중 [4수01-11](분수의 크기 비교) →
   [6수01-10](자연수 나눗셈의 몫을 분수로) 같은 쌍은 실질 관련이 약하다. 튜터 UI에서 밀도가 문제되면 갈래별로
   대표 성취기준만 남기는 축약 규칙을 별도로 도입해야 한다.
3. **영역 간 불균형이 크다.** 변화와 관계는 4건뿐이고 3~4→5~6 구간이 0건이다. 고시가 이 영역의 내용 요소를
   학년군마다 다른 이름으로 두었기 때문이며, 근거 없는 쌍을 채우지 않았다.
4. **121개 성취기준 중 79개만 어떤 관계에도 등장한다.** 나머지 42개는 내용 체계표에서 인접 학년군 갈래를 갖지 않거나
   해설에 선행 지목이 없다. official 층의 정의상 정상이며, 나머지는 `pedagogical-candidate` 층이 담당한다.
5. **쪽수 기준 불일치 리스크.** 이 문서의 인쇄 쪽수는 NCIC 배포 PDF(attachmentNo 10003559)를 pdftotext한 텍스트의
   하단 쪽번호 기준이다. 중등 저장소의 같은 별책 사양 모듈은 PDF 페이지 번호를 인쇄 쪽수로 적어 두었으므로,
   두 저장소를 합칠 때 정정이 필요하다.
